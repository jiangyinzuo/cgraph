# REQ-4-5：操作帮助与快捷提示

| 字段 | 值 |
| --- | --- |
| 父需求 | `REQ-4` |
| 状态 | `Implemented` |
| 优先级 | `P1` |
| 目标版本 | `0.1` |

## 目标

快捷键数量增加后，初次使用者仍能在 TUI 内发现完整操作，同时常驻 footer 不被低频命令淹没。

## 需求

- Canvas 模式按 `?` 打开完整操作帮助。
- 帮助覆盖 Canvas、搜索、保存、配置编辑和帮助层自身的键盘与鼠标操作。
- 帮助内容超过可用高度时可以滚动；`Esc`、`q` 或再次按 `?` 只关闭帮助，不退出 cgraph。
- 常驻左下 footer 只提示少量高频命令和 `?` 入口；前缀等待、错误和操作结果仍可临时替换常驻提示。

## 验收条件

- `?` 打开覆盖画布的帮助层，关闭后图状态和 viewport 不变。
- 帮助层中的完整快捷键清单与当前生产键位一致。
- 小终端中可以通过方向键、`j`/`k`、PageUp/PageDown、Home/End 或鼠标滚轮查看被裁剪内容。
- 帮助层打开时，普通 Canvas 命令不会透传到图。
- 默认 footer 不再枚举所有低频命令，但明确提示 `?` 可以查看完整帮助。

## 实现证据

- `src/tui/help.rs` 维护完整帮助清单、滚动输入和自适应 modal 渲染。
- `src/tui/mod.rs` 在其他 Canvas 命令前分发帮助事件，并把常驻 footer 缩减为高频入口。
- TUI 测试验证 Shift 修饰的 `?`、帮助输入拦截、键鼠滚动、完整内容渲染、无状态副作用和精简 footer。
