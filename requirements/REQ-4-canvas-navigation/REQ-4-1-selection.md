# REQ-4-1：节点选择与导航

| 字段 | 值 |
| --- | --- |
| 父需求 | `REQ-4` |
| 状态 | `Implemented` |
| 优先级 | `P1` |
| 目标版本 | `0.1` |

## 需求

选中节点时应以加粗边框明确表示。用户可以鼠标单击节点，或使用方向键及 `h`、`j`、`k`、`l` 在可见关系上移动选择。

## 验收条件

- 任意时刻至多有一个主选中节点。
- 鼠标视觉区域和实际命中区域一致。
- 键盘移动依据画布空间关系，不依赖节点数组偶然顺序。
- 键盘导航只选择当前可见节点；接受搜索结果会把对应 anchor 重新定位到中心可见窗口。
- 鼠标单击或键盘导航选择已有节点时，该节点在 viewport 中的中心位置保持不变，不因成为新选择而跳到画布中心。

## 当前实现与差距

App 保存图中唯一节点选择；画布节点框与鼠标命中共享同一份 `CanvasLayoutSnapshot`，单击任意可见节点会设置唯一主选择，单击 toggle 按钮也会先选择对应节点。世界布局的节点相对顺序不依赖 selection；交互层在选择前后比较目标节点中心，并用等量 viewport 平移抵消世界原点变化，因此节点保持在用户点击或键盘导航前的位置。

方向键和 `h`、`j`、`k`、`l` 使用节点框中心坐标导航：先限定在目标方向半平面内，再以二维距离、垂直于移动方向的偏移和主方向距离依次排序。它不依赖 anchor 或 neighbor 在数组中的偶然顺序；目标方向没有可见节点时保持当前选择。

## 实现证据

- `CanvasLayoutSnapshot`、鼠标命中和几何导航位于 `src/tui/`。
- App 的图节点选择状态迁移位于 `src/app.rs`。
- 单击选择、左右按钮以及四方向键盘导航都有 TUI 单元测试；回归断言同时比较选择前后的目标节点投影槽位。
