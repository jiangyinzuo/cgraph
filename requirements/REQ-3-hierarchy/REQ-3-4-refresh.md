# REQ-3-4：单层刷新

| 字段 | 值 |
| --- | --- |
| 父需求 | `REQ-3` |
| 状态 | `Implemented` |
| 优先级 | `P2` |
| 目标版本 | `0.1` |

## 需求

选中节点后按 `r`，刷新该全局唯一语义节点的左右一层孩子，不递归重新查询更深层级。

## 验收条件

- 刷新同时查询目标节点左右一层关系。
- 新旧结果中仍存在的孩子复用原节点实例和展开状态。
- 已不存在的孩子及其可见后代从对应分支移除。
- 新孩子以收起状态加入。
- 图模型中的全局唯一语义节点获得一致的左右一层结果，不创建路径副本。
- 刷新期间旧缓存和当前展开状态继续保留；失败时显示错误但不清空旧结果。
- 连续刷新使用新的 request id，较早请求的迟到结果不能覆盖最新状态。

## 当前实现与证据

Canvas 模式的裸 `r` 会通过 App 同时生成 incoming/outgoing 两个 `CachePolicy::Refresh` 请求。刷新成功使用 `RelationGraph::replace_branch_neighbors` 只替换对应一层 observation；按 resolved identity 复用旧节点，因此仍存在孩子的深层缓存和展开状态不变。新孩子由图模型以默认收起、未加载状态创建，消失的孩子不再由该分支可达。

刷新失败恢复请求前的稳定 load state，并保留 neighbors；每个方向独立使用 active request id 拒绝更早结果。App 单元测试覆盖节点复用、深层状态、新增/移除、失败保留和迟到结果，TUI 输入测试覆盖 `r` 同时调度两个方向。
