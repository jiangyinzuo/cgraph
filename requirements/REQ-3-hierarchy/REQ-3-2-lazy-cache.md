# REQ-3-2：懒加载与缓存

| 字段 | 值 |
| --- | --- |
| 父需求 | `REQ-3` |
| 状态 | `Implemented` |
| 优先级 | `P1` |
| 目标版本 | `0.1` |

## 需求

LSP 或 Tree-sitter 查询采用懒加载：某方向首次展开时才请求一层孩子。成功结果写入缓存，收起不清除数据。

## 验收条件

- 未展开节点不主动执行 hierarchy 子节点查询。
- 再次展开成功缓存的分支不重复请求。
- 多层展开后，祖先收起再展开时恢复此前的深层展开状态。
- 左、右单层结果按全局语义身份复用节点；每个分支的 neighbor 顺序保持 provider 首次出现顺序，同一规范边可记录多个查询方向来源。
- 错误和取消结果不写入永久成功缓存。
- 显式刷新可以绕过当前层缓存。

## 当前实现与差距

LSP 与 Tree-sitter 都通过统一可克隆 client 进入现有惰性加载状态机。混合 client 在每次 hierarchy 查询前检查 LSP capability；支持时走 LSP，不支持时走同语言 Tree-sitter 后备，不能通过制造 `Method not found` 错误探测能力。Tree-sitter 在第一次搜索、纯静态展开或能力回退时以 single-flight 后台任务建立项目索引；并发请求共享构建结果，首个搜索等待任务被取消也不会取消或重启项目扫描。之后搜索、左右展开和刷新复用同一份定义与关系数据；构建失败不缓存并允许重试。分支级缓存、错误重试和 request-id 过期结果拒绝仍由 App/State 统一处理。成功空结果会进入 `Loaded`，错误不会写入成功缓存，`REQ-3-4` 的显式刷新可以绕过当前层缓存。

实现测试覆盖 Rust 限定方法名、双向调用、未注册 LSP type hierarchy 时不发送协议请求并回退 Rust trait impl、Python 方法与继承及同类方法优先绑定、C 调用、C++ 类外方法定义与继承、构建目录排除、取消首个等待任务后的单次索引复用，以及 Tree-sitter 静态置信度提示。
